# 第1回デモ: Metasploitable で見る攻撃の流れ

## テーマ

攻撃はどう進むのか

## 目的

- `nmap` が何のために使われるかを理解する
- 攻撃者が最初にサービスを列挙する理由を知る
- HTTP サービスを入口に、脆弱性の危険性をイメージする
- どこで防げたかを考えられるようにする

## 想定構成

```text
[会場PC]
   |
   | SSH
   v
[研究室PC]
   |
   | Host-only / Internal Network
   v
[Metasploitable3 Ubuntu]
```

## 事前準備

1. 研究室PC上で `Metasploitable3 Ubuntu` を起動する
2. 脆弱VMのIPを確認する
3. 会場PCから研究室PCへ SSH できることを確認する
4. `nmap` が研究室PC上で使えることを確認する
5. スナップショットまたはロールバック手段を用意する

## デモの流れ

### 1. 前提説明
- 今回の対象は研究室PC上の隔離された脆弱VMだけである
- 大学ネットワークや研究室LAN全体は対象にしない
- 目的は攻撃の流れと防御ポイントの理解である

### 2. 対象確認
- `Metasploitable3 Ubuntu` のIPを表示する
- 対象IPが単一であることを確認する

### 3. 偵察
- `nmap` で対象IPを調べる
- どのポートが開いているかを見る
- HTTP, SSH, Microsoft-DS などが見えることを説明する

### 4. 列挙の意味を説明
- 攻撃者は最初に「何が開いているか」を調べる
- 不要なサービスや古いサービスが多いほど攻撃面が広がる
- 1つのHTTPサービスだけでなく、複数の入口があることを強調する

### 5. HTTPサービスを見る
- ブラウザまたはテキストベースの方法で HTTP サービスへアクセスする
- トップページは普通の研究室サイトのように見えることを確認する
- `gobuster` で隠しパスを列挙し、`/staff.php` を見つける
- `/staff.php` は職員向けログインフォームに見えることを確認する

### 6. OSコマンドインジェクションを示す
- 職員IDに `admin`、パスワードに任意の値を入力し、`/staff_result.php` へ遷移して `id` コマンドのエラーがそのまま表示されることを確認する
- 職員IDに `admin; whoami` を入力し、遷移先に `whoami` の結果として `www-data` が表示されることを確認する
- 入力値がOSコマンド文字列へ直接連結される危険を説明する
- 実演では `whoami`, `hostname`, `id` のような安全な確認コマンドのみを扱う
- ここでは権限昇格や外部通信には進まない

### 7. cronの権限設定ミスを確認する
- 職員IDに `admin; cat /etc/cron.d/sidlab-maintenance` を入力し、rootが定期実行するジョブを確認する
- 職員IDに `admin; ls -l /opt/sidlab/maintenance.sh` を入力し、rootが実行するスクリプトが `root:www-data` かつ `rwxrwxr-x` になっていることを確認する
- rootが実行するファイルをWebサーバユーザー側から書き換え可能にしている点が権限設定ミスであることを説明する
- この回ではcronスクリプトの書き換えやroot権限コマンド実行までは行わない

### 8. どこで防げたか
- 不要なサービスを止める
- 古いソフトウェアを更新する
- 入力値をOSコマンドに直接連結しない
- 可能なら shell を呼ばず、安全なAPIや固定引数で処理する
- IPアドレスやホスト名を許可リストで検証する
- rootのcronが実行するファイルをWebサーバユーザーに書き換えさせない
- 権限を最小化する
- ログ監視と構成管理を行う

## 第1回で見せたいメッセージ

- 攻撃はまず偵察から始まる
- サービスが見えているだけで攻撃面になる
- HTTP は身近だが危険な入口にもなり得る
- 見た目が普通の業務ツールでも、入力処理が危険ならOSコマンド実行につながる
- 防御は侵入後ではなく、サービス公開や設定の段階から始まる

## この回でやらないこと

- reverse shell
- root 取得
- 認証情報窃取
- 横展開
- DoS
- 外部ネットワークへの接続

## 次回へのつなぎ

- 第1回では攻撃の入口を見た
- 第2回では、もし低権限で侵入された後に設定ミスがあると何が起きるかを扱う
