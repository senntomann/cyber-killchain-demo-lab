# アーキテクチャ

## 目的

攻撃デモの通信を、研究室PCとその上で動く脆弱VMの間に閉じ込める。

## 全体構成

```text
[会場PC]
   |
   | SSH
   v
[研究室PC]
   |
   | Host-only / Internal Network
   v
[脆弱VM]
```

## 役割

### 会場PC
- 発表時の操作端末
- 研究室PCへ SSH 接続するだけ
- `nmap` や `metasploit` は原則ここでは実行しない

### 研究室PC
- 攻撃ツールの実行ホスト
- `nmap`、`metasploit`、必要なら補助ツールを動かす
- 脆弱VMへ到達できる唯一のホストにする

### 脆弱VM
- デモ対象
- 研究室PCからのみ見える隔離ネットワークに置く
- 研究室LANおよびインターネットへ直接出さない

## ネットワーク方針

### 推奨
- `Host-only Adapter`
- `Internal Network`

### 避ける
- `Bridged Adapter`

理由:

- `Bridged` にすると脆弱VMが研究室LAN上の1台として見える可能性がある
- 誤って他のホストへスキャンや攻撃パケットを飛ばすリスクが上がる

## デモ中の通信

### 許可したい通信
- 会場PC -> 研究室PC の SSH 通信
- 研究室PC -> 脆弱VM のデモ用通信

### 避けたい通信
- 会場PC -> 研究室LAN全体
- 会場PC -> 脆弱VM への直接攻撃通信
- 脆弱VM -> 研究室LAN
- 脆弱VM -> インターネット

## 運用イメージ

1. 会場PCから研究室PCへ SSH 接続する
2. 研究室PCで脆弱VMのIPを確認する
3. 対象IPを脆弱VM単体に固定して `nmap` を実行する
4. 必要なら `metasploit` を使って最小限のデモを行う
5. デモ後は VM を停止またはスナップショットへ戻す
