# スライド構成案：第1回 攻撃の流れを知る（偵察から遠隔操作まで）

## スライド1：タイトル
* **タイトル**: 第1回 攻撃はどう進むのか？ 〜偵察からリバースシェルまで〜
* **サブタイトル**: SIDLab セキュリティデモ

## スライド2：本日の目的
* 攻撃者がどのようにシステムの弱点を見つけるか、実際の流れを体験する。
* 「侵入される前」の偵察や列挙がどれほど重要かを知る。
* Webアプリの脆弱性（OSコマンドインジェクション）から、サーバが遠隔操作される（リバースシェル）までの仕組みを理解する。
* **どこで防げたか**を考える視点を持つ。

## スライド3：デモ環境の注意点（安全方針）
* 本デモは、研究室PC内の**完全に隔離された仮想マシン（VM）**に対してのみ行います。
* 大学のネットワークや外部のインターネットへは一切通信しません。
* 実際の攻撃手法（リバースシェル等）を扱いますが、安全に管理された環境内でのみ実施しています。

## スライド4：サイバーキルチェーンとは
* **概念**: サイバー攻撃は一瞬の魔法ではなく、段階的なプロセス（チェーン）である。
* **7つのフェーズ**:
    1. **Reconnaissance (偵察)**: 標的の調査、情報収集。
    2. **Weaponization (武器化)**: 収集した情報をもとに、攻撃用コード（マルウェアやExploit）を作成。
    3. **Delivery (配送)**: 攻撃用コードを標的に送り込む。
    4. **Exploitation (攻撃の実行)**: 脆弱性を突き、コードを実行させる。
    5. **Installation (インストール)**: バックドアなどを設置し、永続化を図る。
    6. **Command and Control (C2/遠隔操作)**: 外部の攻撃者サーバと通信を確立し、命令を受け取る。★本日のゴール
    7. **Actions on Objectives (目的の実行)**: データ窃取、破壊、ランサムウェア展開など。

## スライド5：本日のデモとキルチェーン
* 本日のデモは、キルチェーンの「偵察」から「遠隔操作(C2)」までにフォーカスする。
* **本日のハイライト**:
    * **1. 偵察**: `nmap` と `gobuster` でシステム構成と入口を探る。
    * **4. 攻撃の実行**: WebフォームのOSコマンドインジェクションを利用する。
    * **6. 遠隔操作**: リバースシェルを張って、攻撃者の端末からサーバを直接操作する。
* **防御の考え方**: キルチェーンは「どこか一つの鎖（チェーン）を断ち切れば」攻撃は失敗する。

## スライド6：ステップ1「偵察 (Reconnaissance)」
* **攻撃者の視点**: まず「どこから入れるか」を探す。
* **使用ツール**: `nmap` （ポートスキャン）
* **実演結果**: HTTP (80) や SSH (22) などが開いていることを確認。
* **ポイント**: 不要なサービスが開いているだけで、攻撃面（Attack Surface）が広がる。

## スライド7：ステップ2「列挙 (Enumeration)」
* **攻撃者の視点**: HTTPが開いているなら、隠された管理画面や古いツールがないか探す。
* **使用ツール**: `gobuster` （Webディレクトリ・ファイル列挙）
* **実演結果**: トップページからは見えない `/staff.php` を発見。
* **ポイント**: 「リンクを貼らない」「名前を推測しにくくする」だけでは、アクセス制御にはならない。

## スライド8：ステップ3「潜入の糸口」
* **発見したもの**: 職員専用のログインフォーム (`/staff.php`)。
* **攻撃者の視点**: 入力フォームは、サーバ側のプログラム（PHPなど）にデータを渡す窓口。
* 通常の入力（`admin` / `password`）を試すと、ログイン失敗。
* **違和感**: しかし、結果画面に `id: admin: no such user` というOS側のエラーが表示されている？

## スライド9：ステップ4「OSコマンドインジェクション」
* **実演**: 職員ID欄に `admin; whoami` と入力して送信。
* **結果**: 画面に `www-data` （Webサーバの実行権限）と表示される。
* **何が起きたか**: 開発者がログインIDを `id` コマンドに直接連結するずさんな実装をしていたため、区切り文字 `;` 以降の `whoami` がOSのコマンドとして実行されてしまった。

## スライド10：ステップ5「リバースシェル (遠隔操作の確立)」
* **攻撃者の狙い**: 毎回Webフォームからコマンドを打つのは不便。自分の端末から直接サーバを操作したい（キルチェーンのC2フェーズ）。
* **リバースシェルの仕組み（図解）**: 
  * 通常の通信（正引き）：攻撃者 → 被害サーバ
  * リバースシェル（逆引き）：被害サーバ → 攻撃者（待ち受け）
* **実演・説明**: `admin; [リバースシェルのペイロード]` を送信すると、攻撃者側の端末に接続が来る。
* **脅威**: これにより、Webサーバの権限（`www-data`）で、被害サーバの内部を自由に探索できる対話的なシェルが確立された。

## スライド11：次回のステップ「権限昇格（Privilege Escalation）」
* **攻撃者の次の狙い**: `www-data`（低権限）から `root`（最高権限）を奪いたい。
* **実演・説明**: リバースシェル（またはWeb上）からサーバ内を調べると、`/opt/sidlab/maintenance.sh` というファイルが見つかる。
* **設定ミス**: このファイルは `root` が定期実行（cron）する設定なのに、`www-data` から書き換え可能になっている。
* **脅威**: このスクリプトを書き換えれば、最高権限（root）を奪取でき、システム全体が完全に乗っ取られる。（※今回はここまで）

## スライド12：どこで防げたか（キルチェーンを断ち切る）
1. **ネットワーク（偵察対策）**: 不要なサービスは閉じる。
2. **Web設定（列挙対策）**: 管理画面は推測困難にするだけでなく、アクセス制限（IP制限・認証）をかける。
3. **アプリ実装（攻撃実行対策）**: OSコマンド（`shell_exec`等）を入力値と直接連結しない。
4. **外向き通信制御（遠隔操作対策）**: サーバから外部への不要な通信（リバースシェル）をファイアウォールでブロックする。
5. **OS・権限管理（権限昇格対策）**: rootが実行するファイルを他ユーザーに書き換えさせない。

## スライド13：まとめ
* 攻撃は「偵察 → 列挙 → 脆弱性の利用 → 遠隔操作」とステップを踏んで進む。
* リバースシェルをつながれると、内部探索から権限昇格へと一気に被害が拡大する。
* セキュリティは「侵入された後」ではなく、サービスを公開する前の「設計・設定の段階」での多層防御が重要。
