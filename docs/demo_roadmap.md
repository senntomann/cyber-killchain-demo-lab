# デモロードマップ

## 方針

研究室メンバー向けに、攻撃の流れを段階的に理解してもらう。
初回は攻撃の入口と列挙を重視し、その後に権限昇格や設定ミスの危険へ進む。

## 第1回

### テーマ
- 攻撃はどう進むのか

### 環境
- `Metasploitable2`

### 目的
- `nmap` による偵察とサービス列挙の意味を理解する
- 攻撃者が最初に何を見るのかを知る
- HTTP サービスを入口に、脆弱性のイメージをつかむ

### 見せる内容
- 対象VMのIP確認
- `nmap` でポートとサービスを列挙
- HTTP サービスへアクセス
- Web アプリ上の危険な入力処理の例を説明
- どこで防げたかを整理

### やらないこと
- reverse shell
- 権限昇格
- 永続化
- 横展開
- 外部通信

## 第2回

### テーマ
- 設定ミスによる権限昇格

### 候補
- Linux の `cron`
- Windows タスクスケジューラ

### 目的
- 低権限で入られた後でも、設定ミスがあると危険であることを理解する
- 管理者権限で動く処理のファイル権限が重要だと知る

## 第3回以降の候補

- Windows サービス設定ミス
- 認証情報が狙われる理由の概念説明
- 防御・監査・運用面の整理

## 進め方

1. 攻撃の入口を見せる
2. 侵入後のリスクを見せる
3. それぞれに対する防御策を示す

## 伝えたい共通メッセージ

- 攻撃は魔法ではなく、段階的な情報収集と仮説検証で進む
- 不要なサービス、古いサービス、設定ミスが入口になる
- 攻撃手法そのものより、防御や安全運用につなげることが重要
